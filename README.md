## Repository Structure

```text
playwright-qa-portfolio/

├── .github/
├── pages/
├── tests/
├── test-results/
├── playwright-report/
├── playwright.config.ts
├── package.json
├── package-lock.json
├── tsconfig.json
└── README.md
```
The framework is organised to separate responsibilities clearly. Test logic, page interactions, configuration, reporting, and Continuous Integration are all kept in their own locations, making the project easier to understand, maintain, and extend as it grows.

### Folder & File Explanation

| Folder / File | Purpose |
|---------------|---------|
| **.github/** | Contains GitHub Actions workflows used to automatically run Playwright tests whenever code is pushed to the repository. This helps ensure the framework continues working correctly without requiring manual execution. |
| **pages/** | Stores all Page Object Model (POM) classes. Each page represents a screen in the application and contains reusable locators and page actions. Keeping page interactions separate from test scripts improves readability and makes the framework easier to maintain. |
| **tests/** | Contains the Playwright test specifications. Each test focuses on validating user behaviour and expected outcomes while keeping implementation details inside the Page Objects. |
| **test-results/** | Stores raw execution results generated after running Playwright tests. These files are mainly used for debugging failed test runs and are usually regenerated after each execution. |
| **playwright-report/** | Contains the HTML report generated by Playwright after test execution. The report provides a visual summary of passed and failed tests, execution duration, screenshots, traces, and error details. |
| **playwright.config.ts** | The main configuration file for Playwright. This file controls settings such as browsers, base URL, timeouts, retries, reporters, and other framework-wide behaviour. |
| **package.json** | Defines the project's dependencies, Playwright packages, and reusable npm commands used to install packages and execute tests. |
| **package-lock.json** | Automatically generated by npm to ensure all project dependencies are installed consistently across different machines and environments. |
| **tsconfig.json** | TypeScript configuration file that defines how TypeScript compiles the project, helping maintain consistent coding standards and type safety. |
| **README.md** | Project documentation explaining the purpose of the framework, project structure, setup instructions, and future roadmap. |

## 🚀 Getting Started

This section walks you through setting up the framework from scratch.

Whether you're learning Playwright for the first time or cloning this repository onto a new machine, the steps below will help you get everything running successfully.

Each step includes a short explanation so you'll understand not only **what** to do, but also **why** you're doing it.

## 1. Clone the Repository

Begin by cloning this repository onto your local machine.

```bash
git clone https://github.com/rafhana/playwright-qa-portfolio.git
```

This command downloads a copy of the repository from GitHub into your computer.

After cloning, navigate into the project directory.

```bash
cd playwright-qa-portfolio
```
## 2. Install Project Dependencies

Install all required Node.js packages defined in **package.json**.

```bash
npm install
```

This command downloads all project dependencies required for the framework to run correctly.

You only need to perform this step once after cloning the repository, or whenever new dependencies are added.

## 3. Install Playwright Browsers

Playwright requires browser binaries to execute automated tests.

Install them using:

```bash
npx playwright install
```

This downloads the supported browser engines (Chromium, Firefox, and WebKit) used during test execution.

Like project dependencies, this usually only needs to be done once.

## 4. Verify the Installation

Before writing or running tests, verify that Playwright has been installed correctly.

Run:

```bash
npx playwright test
```

If everything has been configured successfully, Playwright will execute the available test suite and generate a test report.

Seeing your tests run successfully confirms that the framework has been installed correctly.

# ▶️ Running Tests

The framework supports different ways of executing tests depending on what you're trying to achieve.

### Run all tests

```bash
npx playwright test
```

Executes every Playwright test within the **tests** folder.

---

### Run tests in headed mode

```bash
npx playwright test --headed
```

Launches a visible browser window so you can watch each test execute.

This is useful for debugging or understanding the automation flow.

---

### Run Playwright UI Mode

```bash
npx playwright test --ui
```

Starts Playwright's interactive Test Runner, allowing you to execute tests individually, inspect results, and debug failures more easily.

---

### Run a specific test file

```bash
npx playwright test tests/login.spec.ts
```

Runs only the specified test file instead of the full test suite.

Useful while developing or debugging individual features.

# 📊 Viewing Test Reports

After every successful execution, Playwright generates an HTML report.

To open the report:

```bash
npx playwright show-report
```

The report provides detailed execution results, including:

- Passed and failed tests
- Execution duration
- Error messages
- Screenshots (when configured)
- Trace information (when enabled)

HTML reports are extremely useful when analysing failures or reviewing regression test results.
